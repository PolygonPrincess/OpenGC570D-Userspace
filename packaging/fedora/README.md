# Fedora and Universal Blue packaging

These RPM specifications package the immutable OpenGC570D release archive for
Fedora-family distributions and Universal Blue's AKMOD build pipeline.

- `gc570d-kmod.spec` produces `akmod-gc570d` and the matching kernel-specific
  kmod package through `kmodtool`.
- `gc570d.spec` provides the required `gc570d-kmod-common` package, project
  documentation and the system-wide WirePlumber policy.

The kernel module must be built for the exact target kernel. Distribution
builders must sign the completed, uncompressed module before compression or
installation; do not modify the module after signing.

The kmod specification passes `GC570D_DEVELOPER_DEBUGFS=0` so the distributed
module does not register the development `debugfs` interface. Do not apply the
specification to an older source tag that predates this build option: an
unknown make variable would be ignored without providing the separation.

For Universal Blue, these specifications are intended for the
`ublue-os/packages` AKMOD COPR. After the packages build there, the matching
`ublue-os/akmods` integration can consume `akmod-gc570d`, build it for the OGC
kernel and place the resulting signed kmod in the `extra` artifact set.

Before proposing a version update, verify that both specifications reference
the same released OpenGC570D version and source archive.

`gc570d.rpmlintrc` contains only package-specific exceptions for the
source-carrying AKMOD and empty tracking packages generated by `kmodtool`, plus
the historical postal address in the unmodified GPLv2 license text. Run
`rpmlint` with this file against both specifications and every generated RPM.
